# Quick guide for AI coding agents

This repository is a **single-module NeoForge mod** for Minecraft 1.21.x. The build is already successful; the current focus is on running and testing the mod in the NeoForge dev environment.

## Project architecture

- **Single module structure**: All source code lives in `src/main/java` and `src/main/resources`
- **NeoForge-only**: This is a NeoForge-exclusive mod, not a multi-loader project
- **Build system**: Gradle with NeoForge ModDev plugin (v2.0.28-beta)
- **Main dependencies**: Create, Flywheel, Registrate, Ponder, MixinExtras
   - Flywheel is the rendering engine for Create
   - Registrate is used for simplified registration of blocks, items, etc.
   - Ponder is used for in-game tutorials and demonstrations
   - MixinExtras provides additional Mixin features
   - Most of these dependencies are included in the Create mod as transitive dependencies

## Build & run checklist

1. **Build the mod** (already done, use only if needed):
   ```
   ./gradlew build
   ```

2. **Run the NeoForge client** for runtime testing:
   ```
   ./gradlew runClient
   ```

3. **Run the NeoForge server**:
   ```
   ./gradlew runServer
   ```

4. **Run data generation** (when you change registries or data):
   ```
   env$DATAGEN='TRUE';./gradlew runData
   ```
   - Outputs to `src/generated/resources`
   - Make sure to run this when you add/modify blocks, items, or other registry objects

## Important conventions

- **Access transformers**: `src/main/resources/META-INF/accesstransformer.cfg` is the AT file
- **Registrate**: Used for registration — keep registry code organized
- **Gradle properties**: Version numbers and toggles are in `gradle.properties`
- **Java 21**: This project requires Java 21 toolchain

## Testing & debugging

- Always build after making changes: `./gradlew build`
- Run configurations are in the NeoForge ModDev DSL (see `build.gradle.kts`)
- If runtime errors appear, use `./gradlew runClient --stacktrace` for details
- When changing registrations or data, run `$env:DATAGEN='TRUE';./gradlew runData` first

## What to avoid

- Don't add multi-loader or Fabric-specific code/instructions
- Don't hard-code versions — use `gradle.properties`
- Don't create separate platform modules — this is single-module only
- Only fix issues directly related to your task; ignore unrelated test failures

## Quick references
